# ADR 001: Двухоконная архитектура универсального REST API оверлея

**Дата:** 2026-10-10  
**Статус:** accepted  
**Контекст:** Разработка оверлейного приложения для Overwolf с перспективой публикации в Overwolf App Store.

---

## 1. Контекст и проблема

Изначальный прототип (`ttsbard-input-overlay`) решал узкую исследовательскую задачу: проверку перехвата клавиатурного ввода в полноэкранных Direct3D играх без системного курсора мыши (решение проблемы MixMode / Exclusive Mode). 

Для перехода от исследовательского прототипа к полноценному независимому продукту для Overwolf App Store требуется:
1. Универсальность: приложение не должно быть жестко завязано только на один локальный бэкенд, а должно уметь отправлять произвольные REST/Webhook-запросы (локальный TTSBard/Skald, Twitch-боты, Discord, стримерские сервисы, OBS).
2. Разделение обязанностей: удобный интерфейс конфигурации на рабочем столе и сверхлегкий, мгновенный оверлей в игре.
3. Надежный UX внутри игры: автоматический фокус, подтверждение ввода по Enter, отмена по Escape без блокировки игрового процесса.

## 2. Принятое решение

Принята **двухоконная архитектура (Two-Window Architecture)** с централизованным сервисным фоновым контроллером:

```
+-----------------------------------------------------------+
|                   Background Controller                   |
|                      (background.html)                    |
|  - Обработка глобального хоткея                           |
|  - Управление жизненным циклом и фокусом окон             |
|  - Выполнение асинхронных сетевых REST-запросов (fetch)   |
|  - Синхронизация конфигурации и статуса                   |
+-----------------------------+-----------------------------+
                              |
              +---------------+---------------+
              |                               |
              v                               v
+-----------------------------+ +-----------------------------+
|    Desktop Settings Window  | |    In-Game Overlay Window   |
|        (desktop.html)       | |        (overlay.html)       |
|  - Настройка REST URL       | |  - Прозрачный компактный HUD|
|  - Метод (GET/POST/PUT)     | |  - Мгновенный авто-фокус    |
|  - JSON-шаблон и заголовки  | |  - Enter -> Отправка + скрытие|
|  - Геометрия оверлея (W/H)  | |  - Escape -> Отмена + скрытие|
|  - Тестирование запросов    | |  - ReleaseOnHidden эксклюзив|
+-----------------------------+ +-----------------------------+
```

### 2.1. Фоновый контроллер (`background.html`)
- Работает в фоне как `is_background_page: true`.
- Слушает глобальный хоткей через `overwolf.settings.hotkeys.onPressed`.
- Переводит окно ввода в эксклюзивный режим (`restore` -> `bringToFront` -> `requestOverlayFocus`).
- Выполняет сетевой запрос `fetch()` в фоне. Изоляция сети от оверлея гарантирует, что оверлей мгновенно закрывается по нажатию Enter, возвращая контроль игре без ожидания сетевого ответа.

### 2.2. Главное окно настроек (`desktop.html`)
- Обычное десктопное окно с полной поддержкой мыши и клавиатуры.
- Позволяет задать:
  - URL эндпоинта;
  - HTTP-метод (`GET`, `POST`, `PUT`);
  - Шаблон JSON-пейлоада с плейсхолдером `{text}`;
  - HTTP-заголовки (JSON-объект);
  - Размеры оверлея (ширина и высота в пикселях);
  - Интерактивную проверку тестового запроса (Test Request).
- Сохраняет конфигурацию в `localStorage` и через IPC передает контроллеру.

### 2.3. Игровой оверлей (`overlay.html`)
- Регистрируется с `transparent: true`, `in_game_only: true`, `focus_game_takeover: "ReleaseOnHidden"`, `grab_keyboard_focus: true`.
- При открытии мгновенно переводит фокус в инпут.
- Обрабатывает `Enter`: считывает введённый текст, передаёт в background на отправку, немедленно сворачивается (`overwolf.windows.minimize`).
- Обрабатывает `Escape`: немедленно сворачивается без отправки.

## 3. Последствия и преимущества

- **Требования магазина Overwolf:** Архитектура полностью соответствует официальным гайдлайнам Overwolf (наличие десктопного окна настроек + in-game оверлея).
- **Нулевая задержка в игре:** Игрок не «зависает» в оверлее при медленной сети или сетевом сбое.
- **Гибкость:** Пользователь может настроить интеграцию с любым внешним REST API.
